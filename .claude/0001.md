# Planejamento geral

O backlog foi organizado em **6 módulos** com duas fases de entrega. Antes de qualquer módulo, há um pré-requisito de infraestrutura que afeta tudo.

---

## Pré-requisito: reorganização de pastas (módulos como pacotes)

Você mencionou que `controller/books` deveria ser uma pasta, não um arquivo. Esse padrão precisa ser estabelecido antes de gerar código automaticamente, porque o `CrudGen` vai usar esse template.

**Estrutura proposta:**
```
controller/
  __init__.py
  auth.py              ← mantém arquivo único (sem CRUD gerado)
  web.py               ← idem
  books/               ← pasta-pacote
    __init__.py        ← exporta book_bp
    views.py           ← rotas web (list, detail, form)
    forms.py           ← WTForms ou validação manual
api/routes/
  books/
    __init__.py        ← exporta book_api_bp
    endpoints.py       ← REST JSON
services/
  books/
    __init__.py        ← exporta BookService
    service.py
    validators.py
tests/
  books/
    __init__.py
    test_views.py
    test_service.py
    test_api.py
templates/
  books/
    list.html
    detail.html
    form.html
    menu.yaml
```

O `register_core_blueprints` do `main.py` passa a usar um loader automático (parte do `CrudGen`).

## Fase 1 — fundação

### Módulo 1: SmartList (listas inteligentes)

**O que é:** Um componente reutilizável de listagem que qualquer CRUD gerado herda automaticamente.

**Funcionalidades:**
- Filtros dinâmicos configuráveis por YAML (quais campos filtrar, tipo de filtro: texto, select, range, data)
- Pesquisa full-text no lado servidor
- Ordenação por coluna com estado persistido
- Reposicionamento de colunas via drag-and-drop (frontend JS, salvo via API)
- Layout salvo por usuário (tabela `user_layout_prefs`) — opção de tornar público para outros usuários
- Paginação configurável: 10 / 20 / 50 / 100 por página
- Contador de registros (badge com total)
- Export: Excel (openpyxl), CSV (stdlib), PDF horizontal (reportlab ou weasyprint) com cabeçalho

**Arquitetura:**
```
utils/
  smart_list/
    __init__.py
    config.py        ← SmartListConfig (dataclass)
    renderer.py      ← gera contexto para templates
    export.py        ← Excel, CSV, PDF
    models.py        ← UserLayoutPrefs (tabela SQLAlchemy)
templates/
  _components/
    smart_list.html  ← macro Jinja2 reutilizável
    smart_list_filters.html
```

**Entregáveis que preciso gerar:**
1. `model/user_layout_prefs.py`
2. `utils/smart_list/` completo
3. `api/routes/layout_routes.py` (salvar/carregar layout)
4. Template macro `_components/smart_list.html`
5. Exemplo integrado no `books/list.html`

### Módulo 2: CrudGen (gerador de código via CLI)

**O que é:** `flask gen <comando>` que lê um Model e gera controller + api/routes + service + tests + registra BP + cria tabela — tudo num template versionado.

**Comandos:**
```bash
flask gen scaffold books          # gera tudo do zero
flask gen scaffold books --dry-run  # preview sem gravar
flask gen scaffold books --force    # sobrescreve (com backup)
flask gen list                    # lista módulos gerados
flask gen status books            # diff entre gerado e atual
```

**Controle de versão YAML:**
```yaml
# .crud_registry/books.yaml
module: books
model: model.book.Book
version: 2
generated_at: "2026-06-02T10:30:00"
files:
  - path: controller/books/__init__.py
    checksum: sha256:abc123...
    custom_regions: []     ← blocos marcados pelo usuário
  - path: api/routes/books/endpoints.py
    checksum: sha256:def456...
    custom_regions:
      - name: my_custom_endpoint
        start_line: 87
        end_line: 102
```

**Proteção de código customizado:**
```python
# === CUSTOM BEGIN: my_custom_endpoint ===
@book_api_bp.route("/export/special", methods=["GET"])
def special_export():
    ...
# === CUSTOM END: my_custom_endpoint ===
```
O gerador detecta esses blocos, preserva o conteúdo, e reinjecta após regenerar.

**Templates do gerador** (Jinja2 em `utils/crud_loader/templates/`):
- `controller/__init__.py.j2`
- `controller/views.py.j2`
- `api/endpoints.py.j2`
- `services/service.py.j2`
- `tests/test_views.py.j2`
- `tests/test_api.py.j2`
- `templates/module/list.html.j2` (já usa SmartList macro)
- `templates/module/form.html.j2` (com autosave/draft)
- `templates/module/detail.html.j2`

**Auto-registro de BP** em `main.py` — em vez de listar manualmente:
```python
# main.py — register_core_blueprints
from utils.crud_loader import auto_register_blueprints
auto_register_blueprints(app)  # varre .crud_registry/ e registra tudo
```

## Fase 2 — ferramentas avançadas

### Módulo 3: QueryStudio (área de consulta ao banco)

**O que é:** Uma interface web dentro do sistema para explorar, consultar e modificar dados diretamente.

**Funcionalidades:**
- Browser de tabelas: lista todas as tabelas, mostra schema (colunas, tipos, PKs, FKs)
- Editor de query com syntax highlight (CodeMirror ou Monaco lite)
- Execução de queries SQLAlchemy text() com resultado paginado em grid
- Suporte a JOINs e subqueries
- Edição inline de células (UPDATE via PATCH)
- Histórico de queries por sessão
- Proteção: apenas admins, queries destrutivas (DROP/TRUNCATE) bloqueadas

**Arquitetura:**
```
utils/
  query_studio/
    __init__.py
    executor.py      ← wraps db.session.execute com sanitização
    schema.py        ← introspect engine.inspect()
    history.py       ← QueryHistory model
api/routes/
  query_studio_routes.py
controller/
  query_studio.py
templates/
  query_studio/
    index.html       ← Monaco + grid de resultados
```

**Portabilidade:** como está em `utils/`, pode ser copiado para outros projetos Flask que usem SQLAlchemy. Depende apenas de `db/database.py`.

### Módulo 4: ToolBox (ferramentas e console)

**O que é:** Uma área de administração para listar e executar scripts Python e ter um console interativo.

**Funcionalidades:**
- Scanner de `utils/` e diretório configurável por `.env` (`TOOL_SCRIPTS_PATH`)
- Listagem com nome, descrição (docstring), tags (via decorador `@tool`)
- Execução de script com parâmetros via form gerado dinamicamente
- Output em tempo real via SSE (Server-Sent Events) ou WebSocket simples
- Console Python interativo em tempo real (linha por linha, `exec()` isolado com namespace por sessão)
- Apenas admins

**Marcação de scripts:**
```python
# utils/meu_script.py
"""Descrição curta do script."""
from utils.tool_registry import tool

@tool(tags=["manutenção", "db"], params={"dry_run": bool})
def run(dry_run=True):
    """Limpa registros orphãos da tabela de notificações."""
    ...
```

### Módulo 5: TaskManager (tasks e threads)

**O que é:** Sistema leve de execução assíncrona, sem Celery (usando `threading` + `queue` padrão Python, evoluindo opcionalmente para APScheduler).

**Funcionalidades:**
- `TaskRunner`: thread pool configurável
- `TaskQueue`: fila com prioridade
- `TaskScheduler`: cron-like via APScheduler (opcional, flag no `.env`)
- Monitor de tasks em execução (status, progresso, logs)
- Parar/cancelar task via UI
- Persistência opcional de histórico em tabela `task_log`

**Integração com ToolBox:** scripts marcados com `@tool(async=True)` vão para a fila.

---

### Módulo 6: FormEngine (forms do CRUD gerado)

**O que é:** A camada de formulário que o `CrudGen` usa para gerar forms HTML consistentes.

**Funcionalidades:**
- Geração de form a partir de campos do Model (tipo, required, max_length)
- Suporte a autosave/draft (já implementado em books)
- Validação client-side (atributos HTML5) + server-side (serviço)
- Campos customizados: FK select (com busca AJAX), upload de arquivo, rich text
- Estado: create / edit / view-only
- Não sobrescreve regiões customizadas (integrado ao CrudGen)
